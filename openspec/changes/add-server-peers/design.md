# Design

## Context

AmneziaWG‑сервер на Linux — это модуль ядра/`amneziawg-go` и `awg-quick` с
конфигом `/etc/amnezia/amneziawg/<if>.conf`, формат как у WireGuard плюс
параметры обфускации, общие для сервера и всех клиентов. Приложение AmneziaVPN
делает то же самое внутри Docker‑контейнера. Нам нужно минимальное и
предсказуемое управление без Docker и без приложения.

## Goals / Non-Goals

**Goals:**
- Источник истины — локальное состояние `awgkeen`; хост получает рендер.
- Выпуск ключа = одна команда (или кнопка), результат сразу пригоден для
  телефона (QR), ПК (`.conf`), AmneziaVPN (`vpn://`) и роутера (этап 4).
- Изменения пиров без разрыва соединений остальных клиентов.

**Non-Goals:**
- Поддержка всех дистрибутивов при установке.
- Импорт существующего сервера, созданного приложением AmneziaVPN.

## Decisions

1. **Скрипты через `remote.Runner`.** Один интерфейс
   `Run(ctx, script, stdin)`: `Local` (`/bin/sh -c`, опционально `sudo -n`) и
   `SSH` (одно соединение, сессия на команду, `knownhosts` или явный
   `insecure_host_key`). Все пути и имена валидируются регулярками и
   экранируются `ShellQuote`; конфиг передаётся через stdin, а не в аргументах.
2. **Состояние локально, приватные ключи клиентов хранятся.** Чтобы конфиг
   можно было выгрузить повторно (QR на новый телефон), ключи клиентов лежат в
   `servers/<name>.json` (0600, запись под flock через tmp+rename). Ротация
   заменяет ключи и PSK.
3. **Адреса.** Сервер — первый адрес подсети, клиенты — наименьший свободный
   `/32`; удалённый адрес переиспользуется.
4. **Параметры обфускации.** Jc 3–10, Jmin 10–50, Jmax ≤ 250 (> Jmin),
   S1/S2 15–150 с `S1+56 ≠ S2`, H1–H4 — различные случайные значения ≥ 5
   (не совпадают с типами сообщений WireGuard). AWG 2.0 (`awg2: true`) — S3/S4
   и непересекающиеся диапазоны H; требует amneziawg ≥ 2.0 у всех сторон.
5. **План деплоя.** Текущий конфиг читается с хоста и сравнивается с
   рендером: отличие секции `[Interface]` → перезапуск интерфейса, отличие
   пиров → `awg-quick strip | awg syncconf` без разрыва. Пиры сравниваются по
   имени и отпечатку ключа+PSK, поэтому план показывает `+/~/-` без секретов.
6. **NAT.** `PostUp/PostDown` с `MASQUERADE` на интерфейс маршрута по
   умолчанию (определяется на хосте или задаётся `nat_interface`);
   `net.ipv4.ip_forward=1` сохраняется в `/etc/sysctl.d/99-awgkeen.conf`.
7. **Отключение клиента** оставляет его в состоянии, но убирает `[Peer]` из
   конфига сервера (комментарий вместо секции).
8. **Авто‑деплой.** CLI и API после изменения пира сразу деплоят (флаг
   `--no-deploy` / `"deploy": false`). Ошибка деплоя не откатывает изменение
   состояния: следующий `server deploy` его применит; ошибка сообщается явно.
9. **Секреты в API.** Конфиги, QR и `vpn://` выдаются только полному токену,
   каждая выгрузка пишется в лог; списки пиров и ответы операций ключей не
   содержат. Изменяющие операции идут под общим мьютексом `serve` (409).
10. **`vpn://`.** Тот же формат, что разбирает этап 4: base64url от
    qCompress(JSON) с контейнером `amnezia-awg` и `last_config`.

## Risks / Trade-offs

- [Приватные ключи клиентов на машине с `awgkeen`] → файл 0600, каталог 0700;
  альтернатива (не хранить) ломает повторную выдачу QR.
- [Ручные правки конфига на хосте перезаписываются] → заголовок в файле,
  `server plan` показывает расхождение до записи.
- [Установка только для Ubuntu] → для прочих ОС — понятная ошибка со ссылкой.
- [Проверено на фейковом хосте, не на реальном VPS] → нужен ручной прогон.
