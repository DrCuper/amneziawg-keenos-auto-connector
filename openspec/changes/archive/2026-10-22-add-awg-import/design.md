# Design

## Context

KeeneticOS поддерживает WireGuard с 3.x, обфускацию AmneziaWG (ASC) — с 4.2:
`interface <name> wireguard asc Jc Jmin Jmax S1 S2 H1 H2 H3 H4`. В 5.1
добавлен AWG 2.0: `… H4 S3 S4 I1 I2 I3 I4 I5`, H‑значения могут быть
диапазонами `low-high`, пустые I‑строки пишутся как `""`. Веб‑интерфейс с 4.3.4
импортирует `.conf` сам, но это ручная операция без идемпотентности.

Известный синтаксис (форум Keenetic, инструкции Amnezia; running‑config):

```
interface Wireguard0
    description "AWG"
    security-level public
    ip address 10.8.1.2 255.255.255.255
    ip mtu 1376
    ip global 32766
    ip tcp adjust-mss pmtu
    wireguard listen-port 51820
    wireguard asc 4 40 70 0 0 1 2 3 4
    wireguard peer <pubkey> !name
        endpoint host:port
        keepalive-interval 25
        allow-ips 0.0.0.0 0.0.0.0
        connect
    !
    up
!
```

Однострочные формы из корня: `interface Wireguard0 wireguard peer K endpoint X`,
`interface Wireguard0 wireguard peer K no allow-ips X`, `no interface Wireguard0`.
`show interface Wireguard0` по RCI — JSON (`state`, `link`, `connected`,
`wireguard.peer[]` с `public-key`, `remote`, `remote-port`, `rxbytes`,
`txbytes`, `last-handshake`, `online`), в консоли — то же дерево текстом с
выравниванием ключей по двоеточию.

## Goals / Non-Goals

**Goals:**
- Идемпотентный импорт: повторный `awg apply` без изменений конфига не
  отправляет ни одной команды.
- Тот же конвейер, что у групп: план, dry‑run, бэкап, блокировка, верификация,
  журнал.
- Ни один ключ не выводится в план, журнал, лог или текст ошибки.
- Не трогать интерфейсы, которые сервис не создавал.

**Non-Goals:**
- DNS из `.conf`, IPv6, AWG 1.5 J1–J3/Itime, `ip global` по умолчанию
  (оператор включает явно `ip_global`).
- Управление сервером и пирами (этап 6).

## Decisions

1. **Интерфейс — часть `router.Desired`.** `Desired.Interfaces` описывает
   управляемые интерфейсы целиком (пиры не из списка удаляются), не
   перечисленные интерфейсы не трогаются. Синхронизация групп передаёт пустой
   список и интерфейсы не меняет; импорт AWG передаёт пустые группы без prune.
   Так обе операции используют один `Client.Apply`, одну блокировку и один
   бэкап. Интерфейсы создаются до групп и маршрутов (маршрут может ссылаться
   на новый интерфейс), удаляются — в самом конце.
2. **Ключи write‑only.** В running‑config большинства прошивок ключей нет,
   поэтому сравнить их нельзя. Команда ключа попадает в план, когда интерфейса
   или пира ещё нет, когда вызывающий выставил `SetKeys` (отпечаток sha256
   ключей отличается от сохранённого в `awg.json` после успешного применения)
   или когда прошивка показывает ключ и он другой. Такие изменения помечаются
   `WriteOnly`: при верификации после применения они не считаются
   расхождением. Значения ключей регистрируются в плане как секреты и
   заменяются на `<secret>` в `Plan.String`, `RedactedCommands` и в ошибках
   (`Plan.RedactErr`), включая лог ретраев.
3. **Отрицание у листа.** Для вложенных настроек интерфейса используется форма
   `interface W no <setting>` (подтверждена на форуме для `no allow-ips`);
   удаление интерфейса — `no interface W`. Все строки собраны в
   `internal/router/cli/wg.go`, при расхождении на конкретной прошивке
   правится одно место; верификация поймает тихий no‑op.
4. **Канонические адреса.** Адреса и AllowedIPs хранятся префиксами
   (`0.0.0.0/0`), на роутер уходят как `адрес маска` для IPv4 — так их печатает
   running‑config, и дифф не даёт ложных изменений. ASC сравнивается после
   отбрасывания «хвоста» AWG 2.0 из значений по умолчанию, чтобы 9‑ и
   16‑значная формы одних и тех же параметров считались равными.
5. **Выбор интерфейса.** `auto` берёт наименьший свободный `Wireguard<N>` с
   учётом интерфейсов роутера, уже закреплённых туннелей и явных интерфейсов
   других туннелей. Имя резервируется в `awg.json` до применения: если
   применение упало на середине, следующий запуск продолжит тот же интерфейс,
   а не создаст ещё один. Явный интерфейс, существующий на роутере и не
   записанный в `awg.json`, требует `adopt: true`.
6. **`vpn://`.** Ключ — base64url от Qt `qCompress` (4 байта длины + zlib) или
   от JSON без сжатия; внутри `containers[].<proto>.last_config` — JSON со
   строкой `config` (текст `.conf`). Плейсхолдеры `$PRIMARY_DNS`/
   `$SECONDARY_DNS` подставляются из `dns1/dns2`. Контейнеры без WireGuard
   (OpenVPN, XRay) — ошибка.
7. **Здоровье.** Туннель здоров, если интерфейс существует, поднят и хотя бы у
   одного пира handshake моложе `max_handshake_age` (5 мин: при keepalive 25 с
   WireGuard обновляет handshake каждые 2 мин). `last-handshake` больше 2^30
   или 0 без принятого трафика — «handshake не было». Отключённый туннель
   (`enabled: false`) здоров, если интерфейс существует. Сбой — сигнал
   `awg_down:<tunnel>` в алертер этапа 3; имя туннеля не может совпадать с
   именем хука `health.checks` с тем же алертом.
8. **Разбор `show` в консоли.** Ключи выровнены вправо, поэтому уровень
   вложенности — колонка двоеточия, а не отступ. Ключ без значения открывает
   объект, повтор ключа превращает значение в список — получается то же дерево,
   что JSON RCI, и один `ParseWGStatus` на оба транспорта.
9. **Права на файл.** `.conf` содержит приватный ключ; если файл доступен
   группе/всем, импорт выводит предупреждение (но не падает).

## Risks / Trade-offs

- [Синтаксис `no` у вложенных настроек может отличаться между версиями] →
  команды в одном файле; верификация после применения ловит расхождения.
- [Ключ не меняется на роутере, если его поменяли руками] → `--force-keys`;
  проверка handshake покажет проблему.
- [AWG 2.0 на прошивке < 5.1 — команда `asc` с 16 значениями отвергается] →
  предупреждение при разборе, ошибка роутера видна в выводе (без ключей).
- [Формат `last-handshake` разный по версиям] → устойчивый разбор: число,
  строка, «никогда» по большому значению.
