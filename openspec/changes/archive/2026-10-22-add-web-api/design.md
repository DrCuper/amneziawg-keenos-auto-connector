# Design

## Context

`serve` — долгоживущий процесс с планировщиком cron, монитором проверок и
ротацией журнала. Все операции (sync, rollback, ручные правки, импорт
туннелей) уже существуют как методы `syncer.Syncer` и `awg.Manager` и пишут в
журнал через наблюдателей. API должен быть тонким слоем над ними.

## Goals / Non-Goals

**Goals:**
- Всё, что делает CLI в повседневной работе, доступно по HTTP и из браузера.
- Безопасно по умолчанию: без токена — только loopback; ключи AWG и токены
  никогда не возвращаются.
- Нет гонок между API и cron.

**Non-Goals:**
- Многопользовательский доступ, аудит по пользователям.
- SPA‑фреймворки, сборка фронтенда, внешние CDN.

## Decisions

1. **stdlib `net/http` с шаблонами Go 1.22** (`GET /api/v1/groups/{name}`).
   Роутер‑библиотека не нужна; меньше зависимостей.
2. **Два токена.** `token` — всё, `read_token` — только GET (POST с ним — 403).
   Сравнение за постоянное время. Конфиг отклоняет `listen` не на loopback без
   `token`, токены короче 16 символов и одинаковые токены. Cookie не
   используются — токен идёт в заголовке, поэтому CSRF неприменим.
3. **Один мьютекс операций.** `serve` создаёт `sync.Mutex`: планировщик берёт
   его с ожиданием, импорт туннелей при старте — тоже, API — `TryLock`, и при
   занятости отвечает 409, а не висит. Чтения мьютекс не берут.
4. **Источник `api`.** API работает с копией `Syncer` с
   `DefaultTrigger=api`: синхронизации, откаты и ручные правки из API видны в
   журнале как `trigger: api` без изменения сигнатур методов.
5. **Ответ операций = запись журнала.** `sync`, `rollback`, `tunnels/apply`
   возвращают `{"ok", "entry", "summary", "plan", "error"}`, где `entry` —
   `journal.FromReport/FromApply`: один формат для журнала, API и UI. Ошибка
   операции — 422 (409 при блокировке роутера), тело всё равно содержит план.
6. **Метрики без зависимостей.** `/metrics` пишет текстовый формат Prometheus
   вручную: `awgkeen_up`, `awgkeen_check_ok`, `awgkeen_alert_active`,
   `awgkeen_group_entries`, `awgkeen_group_applied_version`,
   `awgkeen_last_sync_timestamp_seconds`, `awgkeen_last_sync_ok`. Требует
   токен (как остальные GET).
7. **UI — один файл через `embed`.** Ванильный JS, DOM строится через
   `textContent` (домены из внешних списков не могут внедрить HTML), CSP
   `default-src 'self'`, `frame-ancestors 'none'`. Токен хранится в
   `localStorage` браузера оператора.
8. **Таймауты.** `ReadHeaderTimeout` 10 с, `WriteTimeout` 10 мин (синхронизация
   больших списков), тело запроса ≤ 1 МиБ, неизвестные поля JSON — 400.

## Risks / Trade-offs

- [Токен в `localStorage` доступен скриптам страницы] → своих сторонних
  скриптов нет, CSP запрещает внешние; для доступа извне — HTTPS.
- [Длинная синхронизация держит HTTP‑запрос] → `WriteTimeout` 10 мин; в
  будущем — фоновые задачи с опросом.
- [`/metrics` читает файлы на каждый запрос] → данных мало (группы, журнал с
  конца), частота скрейпа обычно ≥ 15 с.
