# Spec Delta

## Purpose

Веб‑интерфейс для повседневной работы с сервисом из браузера, поверх REST API.

## ADDED Requirements

### Requirement: Встроенная страница
При включённом API и `api.ui` (по умолчанию да) `serve` SHALL отдавать на `/`
встроенную в бинарник страницу без внешних ресурсов. Страница SHALL работать
через REST API с токеном, введённым пользователем и сохранённым в браузере.

#### Scenario: Открытие
- **WHEN** оператор открывает `http://<listen>/` и вводит токен
- **THEN** видна сводка: число групп и туннелей, активные алерты, последняя синхронизация, проверки

#### Scenario: UI выключен
- **WHEN** `api.ui: false`
- **THEN** на `/` нет страницы, API работает

### Requirement: Разделы
Интерфейс SHALL содержать разделы: обзор с запуском синхронизации (план и
применение), группы (версии, записи, ручные правки, откат, открепление),
журнал с фильтрами и подробностями записи, туннели (состояние, план и импорт)
и роутер (группы, маршруты, Wireguard‑интерфейсы). Применяющие действия SHALL
требовать подтверждения.

#### Scenario: Откат из интерфейса
- **WHEN** оператор нажимает «Откатить сюда» у версии и подтверждает
- **THEN** вызывается откат, на странице показан результат и дифф

### Requirement: Безопасный вывод
Данные (домены из внешних списков, описания, ошибки) SHALL выводиться только
как текст. Ответы SHALL содержать `Content-Security-Policy` с
`default-src 'self'`, `X-Frame-Options: DENY` и `X-Content-Type-Options: nosniff`.

#### Scenario: HTML в домене
- **WHEN** в данных встречается строка `<img src=x onerror=...>`
- **THEN** она показана как текст и не исполняется
