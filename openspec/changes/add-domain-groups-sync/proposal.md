# Proposal

## Why

Этап 1 дал клиент роутера: он умеет применить дифф «роутер → желаемое состояние»,
но желаемое состояние пока пишется руками в YAML. Ядро сервиса — собирать
списки доменов из community‑репозиториев, локальных файлов и ручных правок,
нормализовать их, держать историю версий и регулярно синхронизировать с
роутером. Это этап 2 плана из `openspec/project.md`.

## What Changes

- Новый файл описания групп `domains.yaml` (путь в `sync.domains_file`):
  - **подключения** (`connections`): имя → набор `dns-proxy route` (интерфейс AWG,
    шлюз Reality и т. п.); группа ссылается на подключение по имени;
  - **группы**: имя = `object-group fqdn` на роутере, `connection`, `sources`,
    ручные `include` / `remove`, Keenetic‑`exclude`, лимит записей.
- **Источники**: URL‑списки (http/https, условный GET, кэш последней удачной
  копии, лимит размера), локальные файлы. Разбор строк в форматах plain, hosts,
  dnsmasq (`server=/…/`, `ipset=/…/`, `nftset=/…/`), v2fly (`domain:`, `full:`),
  Clash (`DOMAIN-SUFFIX,…`), wildcard `*.example.com`, URL; комментарии и мусор
  отбрасываются со счётчиком.
- **Нормализация**: нижний регистр, IDN → punycode, проверка формата,
  дедупликация, схлопывание поддоменов (группа Keenetic уже покрывает
  поддомены), лимит записей на группу и на все группы (ошибка или обрезка
  по приоритету: ручные → источники по порядку).
- **Ручные правки во время работы**: `awgkeen groups add|remove|clear` хранит
  добавления/исключения в состоянии, без правки YAML.
- **Состояние и версии** в файлах под `state_dir`: история версий каждой группы
  (содержимое, хэш, статистика источников), применённая версия, кэш источников.
  Новая версия создаётся только при изменении содержимого.
- **Синхронизация**: сборка всех групп → `router.Desired` → `Client.Apply`
  (дифф, бэкап, блокировка, проверка — из этапа 1). Dry‑run ничего не пишет
  ни на роутер, ни в состояние. Защиты: упавший источник не опустошает
  группу (используется кэш или предыдущая версия), резкое сокращение списка
  (`max_shrink`) блокируется без `--force`.
- **Откат**: `awgkeen groups rollback <group> [--to N]` закрепляет группу на
  версии N и применяет её; `groups unpin` возвращает автообновление.
- **Расписание**: `awgkeen serve` — демон, запускает синхронизацию по cron
  (`sync.schedule`) и при старте; `awgkeen sync` — ручной запуск. Пересекающиеся
  запуски исключены файловой блокировкой.

Вне scope: журнал изменений и уведомления (этап 3), импорт AWG (этап 4),
REST API / веб‑интерфейс (этап 5). Пакеты проектируются так, чтобы HTTP‑слой
вызывал те же `Syncer` и `Store`.

## Capabilities

### New Capabilities
- `domain-groups`: описание групп и подключений, источники доменов, нормализация,
  лимиты, ручные правки, история версий и откат.
- `sync-scheduler`: дифф‑синхронизация групп с роутером, dry‑run, защиты от
  опустошения, ручной запуск и запуск по cron.

### Modified Capabilities
(нет — используется существующий API `router-client`)

## Impact

- Новые пакеты: `internal/domains`, `internal/source`, `internal/store`,
  `internal/syncer`; новые CLI‑команды `sync`, `serve`, `groups …`.
- Конфиг: новые секции `state_dir`, `sync`.
- Зависимости: `github.com/robfig/cron/v3` (разбор cron‑выражений),
  `golang.org/x/net/idna` (punycode).
- Внешние системы: HTTP(S)‑источники списков (GitHub raw и т. п.).
