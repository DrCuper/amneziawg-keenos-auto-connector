# Spec Delta

## Purpose

Группы доменов описывают, какие домены и через какое подключение должны
маршрутизироваться. Сервис собирает каждую группу из источников (URL, файлы,
ручные записи), нормализует её, хранит историю версий и умеет откатиться к
любой из них.

## ADDED Requirements

### Requirement: Описание групп и подключений
Сервис SHALL читать описание групп из YAML‑файла (`sync.domains_file`). Файл
содержит `connections` (имя → список маршрутов `dns-proxy route`: интерфейс
или шлюз, `auto`, `reject`) и `groups`. Каждая группа SHALL иметь уникальное
имя (= `object-group fqdn` на роутере) и ссылаться на существующее подключение
по имени через `connection`. Группа MAY задавать `description`, `sources`,
`include`, `remove`, `exclude`, `max_entries`, `collapse_subdomains`.

#### Scenario: Группа привязана к подключению
- **WHEN** группа `awg-main` указывает `connection: awg`, а `connections.awg.routes` содержит `interface: Wireguard0`
- **THEN** желаемое состояние группы содержит маршрут `dns-proxy route object-group awg-main Wireguard0 auto`

#### Scenario: Неизвестное подключение
- **WHEN** группа ссылается на подключение, которого нет в `connections`
- **THEN** загрузка файла завершается ошибкой с именем группы и подключения, синхронизация не запускается

#### Scenario: Дубликат имени группы
- **WHEN** две группы имеют одно имя
- **THEN** загрузка файла завершается ошибкой

### Requirement: Источники доменов
Сервис SHALL поддерживать источники `url` (http/https) и `file` (локальный путь,
относительно файла описания). Каждый источник MAY задавать `format`
(`auto|plain|hosts|dnsmasq|v2fly|clash`; по умолчанию `auto`) и `name`.
URL‑источники SHALL загружаться с таймаутом, ограничением размера
(`sync.source_max_bytes`) и условным GET (`ETag`/`Last-Modified`).

#### Scenario: Загрузка URL‑списка
- **WHEN** источник `url` отвечает 200 с текстом списка
- **THEN** строки разбираются согласно формату, результат попадает в группу, а копия сохраняется в кэше состояния

#### Scenario: Источник не изменился
- **WHEN** в кэше есть `ETag` источника и сервер отвечает 304
- **THEN** используется кэшированная копия без повторной загрузки

#### Scenario: Источник недоступен, есть кэш
- **WHEN** загрузка URL завершилась ошибкой (сеть, 5xx, превышен размер), а в кэше есть прошлая удачная копия
- **THEN** используется кэш, источник помечается как `stale`, сборка группы продолжается с предупреждением

#### Scenario: Источник недоступен, кэша нет
- **WHEN** загрузка URL завершилась ошибкой и кэша нет
- **THEN** сборка этой группы завершается ошибкой; группа на роутере не меняется, другие группы обрабатываются

#### Scenario: Локальный файл
- **WHEN** источник `file: lists/extra.txt` существует
- **THEN** файл читается относительно каталога файла описания и разбирается как список

### Requirement: Разбор строк списка
Парсер SHALL извлекать домены из строк форматов plain, hosts, dnsmasq, v2fly,
Clash и URL; формат `auto` SHALL определять тип построчно. Комментарии
(`#`, `//`, `!`) и пустые строки SHALL игнорироваться. Нераспознанные строки
SHALL отбрасываться и учитываться в статистике источника.

#### Scenario: Форматы строк
- **WHEN** строка имеет вид `example.com`, `*.example.com`, `.example.com`, `0.0.0.0 example.com`, `server=/example.com/1.1.1.1`, `ipset=/example.com/x`, `nftset=/example.com/x`, `address=/example.com/0.0.0.0`, `domain:example.com`, `full:example.com`, `DOMAIN-SUFFIX,example.com`, `DOMAIN,example.com` или `https://example.com/path`
- **THEN** результат разбора — `example.com`

#### Scenario: Пропускаемые директивы
- **WHEN** строка начинается с `regexp:`, `keyword:`, `include:` (v2fly) или типа Clash, отличного от `DOMAIN`/`DOMAIN-SUFFIX` (например `IP-CIDR,…`)
- **THEN** строка пропускается без ошибки, счётчик `skipped` увеличивается

#### Scenario: Смешанный список
- **WHEN** источник содержит `example.com`, `*.cdn.example.net`, `0.0.0.0 ads.example.org`, `server=/x.example.io/1.1.1.1`, `DOMAIN-SUFFIX,y.example.io`, `# comment`
- **THEN** результат — `example.com, cdn.example.net, ads.example.org, x.example.io, y.example.io`

#### Scenario: Мусорная строка
- **WHEN** строка не является ни доменом, ни известной директивой (`???`, `regexp:^foo`)
- **THEN** строка пропускается, счётчик `skipped` источника увеличивается

### Requirement: Нормализация
Сервис SHALL нормализовать записи группы: нижний регистр, обрезка пробелов и
завершающей точки, IDN → punycode, проверка формата (домен или IP/CIDR,
как в `router-client`), дедупликация с сохранением первого вхождения.
При `collapse_subdomains: true` (по умолчанию) записи, чей родительский домен
уже есть в группе, SHALL удаляться. Записи `localhost`, `local`, `*`, IP‑адреса
`0.0.0.0`/`127.0.0.1`/`::1` и домены верхнего уровня без точки SHALL
отбрасываться.

#### Scenario: Дедупликация и регистр
- **WHEN** источники дают `Example.com`, `example.com.`, `EXAMPLE.COM`
- **THEN** в группе одна запись `example.com`

#### Scenario: Схлопывание поддоменов
- **WHEN** в группе есть `example.com` и `api.example.com`
- **THEN** остаётся только `example.com`

#### Scenario: IDN
- **WHEN** источник содержит `пример.рф`
- **THEN** в группе запись `xn--e1afmkfd.xn--p1ai`

### Requirement: Ручные записи
Группа SHALL принимать ручные `include` (всегда добавляются) и `remove`
(вычёркиваются из результата, на роутер не идут) из файла описания; `exclude`
передаётся на роутер как `object-group fqdn … exclude`. Дополнительно сервис
SHALL хранить ручные добавления и вычёркивания в состоянии
(`awgkeen groups add|remove|clear`), объединяя их с файлом описания.
`remove` SHALL иметь приоритет над любым источником и `include`.

#### Scenario: Ручное добавление через CLI
- **WHEN** выполнено `awgkeen groups add awg-main manual.example.com`
- **THEN** запись сохраняется в состоянии и попадает в следующую сборку группы без правки YAML

#### Scenario: Вычёркивание побеждает источник
- **WHEN** источник содержит `bad.example.com`, а группа задаёт `remove: [bad.example.com]`
- **THEN** `bad.example.com` отсутствует в собранной группе

#### Scenario: Очистка ручных правок
- **WHEN** выполнено `awgkeen groups clear awg-main`
- **THEN** ручные добавления и вычёркивания группы из состояния удалены

### Requirement: Лимит размера
Сервис SHALL ограничивать число записей группы (`max_entries` группы, иначе
`router.max_entries`). Порядок приоритета записей: ручные `include` → источники в
порядке объявления. При превышении лимита при `sync.on_limit: error` (по
умолчанию) сборка группы SHALL завершаться ошибкой; при `sync.on_limit: truncate`
список SHALL обрезаться по приоритету с предупреждением и счётчиком отброшенных.

#### Scenario: Превышение лимита — ошибка
- **WHEN** группа после нормализации содержит 2500 записей при лимите 2000 и `on_limit: error`
- **THEN** сборка группы завершается ошибкой `exceeds limit`, роутер не меняется

#### Scenario: Превышение лимита — обрезка
- **WHEN** те же условия при `on_limit: truncate`
- **THEN** группа содержит первые 2000 записей по приоритету, в результате отмечено `truncated: 500`

### Requirement: Версии группы
Каждая успешная сборка SHALL сравниваться с последней версией группы по хэшу
содержимого; при изменении SHALL создаваться новая версия (номер, время, хэш,
записи, exclude, статистика источников). Одинаковое содержимое MUST NOT
порождать новую версию. Сервис SHALL хранить не менее `sync.keep_versions`
(по умолчанию 10) последних версий и запоминать номер версии, применённой к
роутеру.

#### Scenario: Содержимое не изменилось
- **WHEN** повторная сборка дала тот же набор записей
- **THEN** новая версия не создаётся, номер последней версии не меняется

#### Scenario: Содержимое изменилось
- **WHEN** сборка дала другой набор записей
- **THEN** создаётся версия N+1, предыдущие версии остаются доступными для отката

#### Scenario: История
- **WHEN** выполнено `awgkeen groups history awg-main`
- **THEN** выводятся версии с номером, временем, числом записей, разницей с предыдущей и отметкой применённой

### Requirement: Откат к предыдущей версии
`awgkeen groups rollback <group> [--to N]` SHALL закрепить группу на версии N
(по умолчанию — на версии, предшествующей применённой) и применить её на роутер
диффом. Пока группа закреплена, автообновление SHALL использовать закреплённую
версию вместо сборки из источников. `awgkeen groups unpin <group>` SHALL снять
закрепление.

#### Scenario: Откат на предыдущую версию
- **WHEN** применена версия 5 и выполнено `groups rollback awg-main`
- **THEN** группа закреплена на версии 4, на роутер отправлен дифф 5 → 4, применённая версия = 4

#### Scenario: Закреплённая группа при автообновлении
- **WHEN** группа закреплена на версии 4 и запускается `sync`
- **THEN** источники для группы не загружаются, желаемое состояние = версия 4

#### Scenario: Откат на несуществующую версию
- **WHEN** `--to` указывает версию, которой нет в истории
- **THEN** команда завершается ошибкой, роутер и состояние не меняются

### Requirement: Состояние в файлах
Состояние (версии, применённая и закреплённая версии, ручные правки, кэш
источников) SHALL храниться в файлах под `state_dir` в формате JSON; записи
SHALL быть атомарными (временный файл + rename). Повреждённый или
отсутствующий файл конкретной группы MUST NOT ломать работу с другими группами.

#### Scenario: Первый запуск
- **WHEN** `state_dir` пуст
- **THEN** каталоги создаются, все группы собираются как версия 1

#### Scenario: Повторный запуск без изменений
- **WHEN** состояние и источники не изменились
- **THEN** новые версии не создаются, план для роутера пуст
